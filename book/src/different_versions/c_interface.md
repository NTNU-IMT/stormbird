# C interface

The `cstormbird` library is a C interface to Stormbird. Most programming languages can call functions that follow the C calling convention, so the purpose of the library is to make Stormbird available in languages that do not have a dedicated interface, such as C, C++, Fortran, C#, Julia or MATLAB. The functionality is intended to be very similar to the [Python interface](python_interface.md), and the setup is done with the same JSON input, which can be created with the `stormbird_setup` library, for instance from the [default sail models](../lifting_line/complete_sail_model.md#default-sail-models).

The library has two entry points:

- `CompleteSailModel`: the [complete sail model](../lifting_line/complete_sail_model.md), for simulating the sails as a complete system from a wind condition and a ship velocity. This includes the `simulate_optimal_steady_state_condition_simple_output` function, which writes one `SingleSailResult` per sail to an array owned by the caller.
- `LiftingLineSimulation`: a [lifting line simulation](../lifting_line/simulation_overview.md) on its own, for cases where the freestream velocity is computed elsewhere.

## Building
The library is built with Cargo from the `interfaces/cstormbird` folder:

```
cargo build --release
```

This gives a shared library in the `target/release` folder, and a header file, `include/cstormbird.h`, which is generated by [cbindgen](https://github.com/mozilla/cbindgen).

## Example

```c
#include "cstormbird.h"

CompleteSailModel *model = complete_sail_model_new(setup_json_string);
WindCondition *wind = wind_condition_new_constant(1.57, 8.0);

int nr_sails = complete_sail_model_get_number_of_sails(model);
SingleSailResult *results = malloc(nr_sails * sizeof(SingleSailResult));

complete_sail_model_simulate_optimal_steady_state_condition_simple_output(
    model, wind, 6.0, 1.0, results, nr_sails
);

free(results);
wind_condition_drop(wind);
complete_sail_model_drop(model);
```

Structures that cannot be represented directly in C, such as the models, wind conditions and simulation results, are handled as *opaque pointers*. They are created by the `*_new*` functions, which return `NULL` on failure, and must be released with the matching `*_drop` function. Functions that can fail return an error code, and `stormbird_last_error_message` gives a description of the latest failure. See the [cstormbird README](https://github.com/NTNU-IMT/stormbird/tree/main/interfaces/cstormbird) for the full conventions.
